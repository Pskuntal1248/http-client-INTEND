# Environments

<Callout type="info">
Switch between DEV and PROD from the workspace header. URLs and credentials update instantly based on the active environment.
</Callout>

## Quick Flow

<Steps>
### Select environment

Choose **DEV** or **PROD** from the environment dropdown.

### Pick auth strategy

Set `API_KEY`, `BASIC_AUTH`, `BEARER_TOKEN`, or `NONE`.

### Send request

Intend resolves credentials using the active environment only.
</Steps>

## Configuration Fields

| Field | Default | Used by |
|---|---|---|
| `devUrl` | `http://localhost:8080` | DEV base URL |
| `devKey` | empty | DEV API key auth |
| `prodUrl` | `https://api.example.com` | PROD base URL |
| `prodKey` | empty | PROD API key auth |

Config location: `~/.intend/intend-config.json`

```json
{
  "devUrl": "http://localhost:8080",
  "devKey": "dev-api-key",
  "prodUrl": "https://api.example.com",
  "prodKey": "prod-api-key"
}
```

## Credential Resolution Matrix

| Auth strategy | Source keys | Output header |
|---|---|---|
| `API_KEY` | `devKey` or `prodKey` | `X-API-KEY` |
| `BASIC_AUTH` | user and pass for active env | `Authorization: Basic ...` |
| `BEARER_TOKEN` | token for active env | `Authorization: Bearer ...` |

<Callout type="warning">
Environment isolation is strict: DEV credentials are never used while PROD is selected, and vice versa.
</Callout>

## Why This Model

<Cards>
  <Card title="Safe environment separation" href="/docs/features/environments">
    Prevents accidental credential crossover across staging and production.
  </Card>
  <Card title="Per-request auth control" href="/docs/features/environments">
    Auth strategy is part of each request intent, not fixed at collection level.
  </Card>
</Cards>
