# Zero-Config Headers

<Callout type="info">
Intend resolves request headers from intent context (method, URL, auth, payload), so you can send production-like requests without manual header authoring.
</Callout>

## What Intend Resolves Automatically

| Input signal | Header output |
|---|---|
| Body starts with `{` or `[` | `Content-Type: application/json` |
| Body starts with `<` | `Content-Type: application/xml` |
| Plain text body | `Content-Type: text/plain` |
| Empty body | No `Content-Type` |
| Any request | `User-Agent`, `Accept`, `Accept-Language`, `Accept-Encoding` |
| Any request | `Sec-Ch-Ua`, `Sec-Ch-Ua-Platform`, `Sec-Fetch-*` |
| Any request | `Origin`, `Referer` based on target URL |
| Auth strategy = `API_KEY` | `X-API-KEY` |
| Auth strategy = `BASIC_AUTH` | `Authorization: Basic ...` |
| Auth strategy = `BEARER_TOKEN` | `Authorization: Bearer ...` |
| POST/PUT/PATCH | `Idempotency-Key`, `X-Request-ID` |

## Why This Works Better Against WAFs

<Cards>
    <Card title="Consistent browser profile" href="/docs/features/zero-config-headers">
        User-Agent and Sec-Ch-Ua are generated as a coherent browser fingerprint.
    </Card>
    <Card title="Context-aware origin headers" href="/docs/features/zero-config-headers">
        Origin and Referer are derived from the actual target URL, not static placeholders.
    </Card>
    <Card title="Auth and protocol in one pass" href="/docs/features/zero-config-headers">
        Authentication headers and protocol defaults are merged in a single pipeline.
    </Card>
</Cards>

## Provider Pipeline

```text
order 10: ProtocolProvider       -> browser and content headers
order 50: IdempotencyProvider    -> Idempotency-Key, X-Request-ID
order 90: ApiKey/Basic providers -> auth-specific headers
order 91: BearerTokenProvider    -> bearer authorization
```

<Callout type="warning">
If providers emit the same key, the later provider wins.
</Callout>

## Inspect Effective Headers

<Steps>
### Send request

Use any method and payload as usual.

### Open Headers tab

Inspect the exact final set sent on wire.

### Verify auth and payload mapping

Confirm `Authorization` and `Content-Type` match selected auth and payload form.
</Steps>

## Extend the Pipeline

```java
public final class CustomCorsProvider implements HeaderProvider {
        @Override
        public int getOrder() { return 20; }

        @Override
        public boolean supports(ResolutionContext ctx) {
                return !ctx.intent().url().getHost().equals("localhost");
        }

        @Override
        public HeaderResolution resolve(ResolutionContext ctx) {
                return HeaderResolution.success(Map.of("Origin", "https://app.yourcompany.com"));
        }
}
```
